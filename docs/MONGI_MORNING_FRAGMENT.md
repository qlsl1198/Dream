# 몽이의 아침 한 조각

기반: main `6e59eeb` → `feat/dream-evidence-first` (`024c130`) → `feat/mongi-morning-fragment`.
홈에서 짧게 기억나는 낱말을 남기는 모드다. 감정·태그·해석 버튼은 잠시 숨기고
기존 본문 입력과 `dream_draft`를 그대로 사용한다. 별도 기록이나 저장 키를 만들지 않는다.
닫기 버튼은 기존 저장 큐에서 본문과 부가 필드의 저장이 성공한 뒤에만 닫는다.
실패 시 현재 입력을 유지하고 다시 시도할 수 있다. 초안은 앱을 다시 열어도 복원되며,
앨범 기록은 사용자가 정식 저장을 눌렀을 때만 생성된다.

재현: 기존 초안에 감정과 태그를 넣고 아침 한 조각에 들어간다. 한 단어를 더 적어
저장하고 닫은 뒤 새로고침한다. 본문·감정·태그가 그대로이고 앨범 건수가 늘지
않는지 확인한다. 별도 기기 권한이나 서버 연동은 없다.

2026-11-24: 두 기능의 누적 소스에서 Node 22로 `npm test`, `npm run typecheck`,
`git diff --check` 통과. 기존 초안 전체 필드의 인코딩·복원 회귀 테스트와
본문 상징·발췌 근거 검사가 포함된다. iOS 실기기, TestFlight 및 심사는 이 작업에서
변경하거나 검증하지 않는다.
Expo 웹(로컬 8099, Aside, 390×844 및 820px)에서 ‘빨간 우산’을 적고
저장한 뒤 새로고침해 원래 본문 입력에서 복원되고 앨범 건수가 늘지 않음을 확인했다.
홈 해석 결과 및 저장 기록에서 발췌가 해석보다 먼저 나오고, 상징 없는 기록에서는
별도 안내가 표시된다. 흰 화면이나 가시적인 오류 오버레이는 없었다.

웹 QA에서 기존 8096/8098 검증에도 있던 React `Maximum update depth exceeded`
경고가 반복됐다. 기록 삭제 버튼도 해당 웹 검증에서 동작하지 않았다.
삭제 경로는 이번 변경에서 수정하지 않았다. 두 사항은 별도 웹 이슈로 조사하며
이번 기능 확인을 웹 전체 무오류나 iOS 실행 통과로 해석하지 않는다.
